# VT STUDIO 图像工具箱 · 6.5

最后更新：2026-10-27

一个窗口整合 **VT Studio 尺寸转换** 与 **缺陷合成**。统一导航、预览和导出，模块切换保留状态。无需账号、GPU 或网络服务。

转换模块直接复用用户本机 VT Studio 5.0 原转换核心；缺陷合成通过局部素材迁移制作训练补充图，不是 CutPaste 论文的完整模型训练复现。原图只读，各批次独立保存。

## 打开工具

GitHub仓库：[tienan2024/vt-studio-toolbox](https://github.com/tienan2024/vt-studio-toolbox)。直接使用请从 [Releases](https://github.com/tienan2024/vt-studio-toolbox/releases) 下载Windows便携包，解压后运行VTStudioToolbox.exe；VTStudioCLI.exe供AI与脚本调用。源码仓库包含必要的原转换核心，不包含Python环境、生产图片、本机验证目录或构建产物。

优先双击桌面“VT STUDIO 工具箱”快捷方式。6.5独立包位于 `release/6.5.0/VTStudioToolbox/VTStudioToolbox.exe`，启动脚本优先打开新版，旧窗口和旧包保留。便携版需保留整个文件夹及_internal，不能只复制EXE。

源码启动：

```powershell
python -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
python app.py
```

国内镜像失败后再考虑其他源。建议独立 Python 3.10 或更高版本环境。

## AI / 脚本调用

便携目录内提供独立 `VTStudioCLI.exe`，不启动GUI，默认返回结构化JSON。执行 `VTStudioCLI.exe info` 查看能力，`VTStudioCLI.exe schema` 获取机器可读契约。支持图像检查、原核心尺寸转换、缺陷素材提取、批量合成和GUI配方复用。详细参数与可复制示例见 [AI命令行接口](docs/04-AI命令行接口.md)。源码运行 `python cli.py info`。

## 尺寸与原点

1. 点击左侧“尺寸与原点”，选择图片文件夹，按需勾选包含子文件夹。
2. 选择图片，设置目标宽高和黑/白填充颜色。左上角 (0,0) 固定，图像内容不拉伸，仅处理右侧和下方。
3. 查看“裁切 / 填充范围”与“输出预览”。范围预览中橙框为目标边界、蓝框为原图边界。预览可缩放，不改变实际输出。
4. 保留“原样复制 XML”时，XML 内容与其内部路径均保持原样；点集坐标不转换。“允许裁切触及标注区域”默认关闭，由原转换核心执行其识别到的 XML 标注保护。
5. 选择与输入分开的输出位置，开始转换；每批创建 `convert_时间_后缀/images/`，所有输出保留原文件名、集中在 images 文件夹。批次根目录另保存 summary.json 和 events.jsonl。
6. 若结果确认为正常 OK 图，可点击“作为 OK 底图送往缺陷合成”。支持灰度 L 和 RGB 底图，NG 素材须使用相同颜色模式。

递归扫描遇到同名图片，或复制 XML 时遇到来自不同目录的同名配套 XML，会拒绝该批，避免集中输出时相互覆盖；请分批处理。输出位置不能在输入目录内部，以免旧输出被重新作为输入。停止转换会保留已经完成的文件与记录。

## 缺陷合成操作

1. **选择图片 / 选择文件夹**：导入同款产品、相同成像条件的真实 OK 图。文件夹仅扫描当前层，避免把输出或 NG 子目录混入底图。
2. **多选 NG 图并逐张圈选**：在“NG 素材池”选择多张图片或文件夹，点击列表逐张取缺陷；每张独立保存素材与生成范围。未圈选项不参与生成。由操作者确认同款、同类缺陷和相似材料，程序不自动判定。详见 [多NG匹配](docs/06-多NG素材池.md)。
3. **添加多个生成范围**：点击平铺的“生成范围”按钮，连续拖动矩形即可追加多个框；在NG或OK上均可设置。每个NG独立保存各框，生成时随机选一个能放入完整缺陷的框，不会使用框间空白。支持删除选中框、撤销上一框、恢复全图，蓝色虚框参考原NG位置。详见 [界面与多范围](docs/08-界面与多范围.md)。
4. **调整参数**：按真实缺陷设置尺寸倍率、旋转、混合强度、羽化和缺陷类别。点击“生成预览”；“换一张预览”使用后续种子查看变化。
5. **检查预览**：滚轮缩放、右键按住拖动平移；浏览模式也可左键拖动。多边形按Enter或右键单击收尾，右键拖动只平移。勾选“显示修改区域”查看实际改动像素。缩放仅影响显示，不改变输出尺寸。
6. **设置数量 → 选择输出文件夹 → 批量生成**：在右下角“批量导出”区选择“本批生成总数”并输入数量，或选“每张 OK 生成”。界面显示预计合计。总数模式严格生成填写数量，按OK列表顺序尽量均匀分配；每张模式合计为OK数×每张数量。每张结果仍从符合颜色/范围/尺寸的NG中随机匹配。详见 [批量数量](docs/07-批量生成数量.md)。
7. **打开结果**：检查图像与标注，再按你的 VT 版本完成标注导入或人工复核。

快捷键：Ctrl+O 打开 OK 图；Ctrl+S 保存配方；Ctrl+P 生成预览；画布 Esc 清除选区。

## 两种合成方式

| 方式 | 处理 | 适用与限制 |
|---|---|---|
| 暗缺陷迁移 | 灰度按亮度、RGB 按各通道与周边背景的比值形成衰减场；每个通道只会变暗 | 黑点、污渍等暗缺陷；保留底图纹理，但这是近似成像，不保证复现材质、立体遮挡或透射物理过程 |
| 纹理粘贴 | 将选中的素材按强度混合到 OK 图上 | 复制真实缺陷外观，也支持亮缺陷；需审核正常纹理是否被一起带入及拼接边界 |

背景参考值由等宽的手动输入和“自动”勾选组成。自动勾选时输入框置灰禁用，内部仍以0表示自动估计；取消后可填1～255。RGB自动分别估计各通道，手动值由三通道共用。亮斑、异色等可使用“纹理粘贴”保留颜色。

尺寸倍率相对素材原像素大小。允许区域必须能容纳缩放、旋转后的完整素材。程序有限次抽样；无法放入时明确报错，不会偷偷缩小素材或越界。羽化在变换后执行，单位为输出图像像素，并限制在素材掩膜内部。

## 缺陷模块输入与输出

- 支持 **8 位灰度 L** 和 **每通道 8 位 RGB** 的 BMP、PNG、TIFF。索引调色板按实际颜色展开为 L 或 RGB。拒绝带透明度、RGBA、16 位、CMYK 及超过 6000 万像素的输入；不会静默丢弃颜色或透明度。TIFF 读取第一页，建议使用单页图像。
- 每个OK/NG组合须同颜色模式。素材池可含灰度和RGB，自动筛选同模式候选；某个OK没有可用NG时在创建批次前报错。不同产品、材料布局或缺陷类别请分池。
- 输出 BMP 保持底图模式：灰度为 `L`、8 位；彩色为 `RGB`、24 位。每张图与来源 OK 图像素尺寸相同，左上角原点不变，不缩放整图。
- 掩膜始终是同尺寸单通道 PNG，只有 0 与 255。255 表示量化后任意颜色通道发生变化的像素；不自动等价于专家定义的语义缺陷范围，需人工复核。
- 旧单素材配方仍可加载；RGB需6.1或更高版本。6.3 GUI保存 `vt-defect-pool/1` 素材池配方，需6.3或更高版本读取，包含各NG独立范围和内嵌素材。
- 默认导出与BMP同名的VT原生缺陷矩形XML，框取实际变化像素外接框；PNG仍保留精细掩膜。格式依据本机VisionTrain标注类并通过原生读取器读回验证；其他任务类型或其他平台XML未混称通用兼容。详见 [VT XML格式](docs/09-VT_XML导出.md)。

```text
run_时间_唯一后缀/
├── images/                  # 原文件名_syn_序号.bmp
├── masks/                   # 与合成图同名的二值 PNG
├── annotations/             # 每张图的通用 JSON
├── manifest.jsonl           # 完成样本清单，每行一个 JSON
├── recipe.json              # 参数、允许区域、内嵌素材与底图路径
├── assets/                  # 素材池内每份素材及其掩膜（无损）
└── summary.json             # complete / cancelled / failed 与完成数量
```

这是GUI/素材池批次布局；CLI `--asset` 单素材直调仍输出 `defect_asset.png` 和 `defect_asset_mask.png`。素材池结果记录具体NG、条目ID和其生成范围，summary.json统计各素材使用次数。

所有坐标以输出原图为准，原点为左上角、x 向右、y 向下。`bbox_xyxy=[left,top,right,bottom]` 使用零基、右下边界不包含的半开区间。`placement_xyxy` 为整个变换素材的放置矩形；`bbox_xyxy` 为实际修改像素的最小外接矩形。`split_group` 为来源 OK 路径，帮助将同一底图的衍生样本放入同一数据集分组。

随机种子控制每张图的参数与位置。批次按底图导入顺序、每张底图生成序号依次使用 `基础种子+样本全局序号`；首张序号为 0。“换一张预览”不修改批次基础种子。完全复现需相同源像素、素材、参数、文件顺序与 Pillow/NumPy 版本；不能承诺不同图像库版本逐像素一致。

取消在当前检查或当前样本完成后生效，完成数据与清单保留。批次发生写盘错误时状态为 failed，可能存在尚未进入清单的文件；后续处理应以 `manifest.jsonl` 中的完成记录为准。

## 配方与数据管理

“保存配方”将素材与掩膜以无损 PNG 内嵌到 JSON，原始 NG 移动后仍可恢复素材；OK 路径失效时需要重新导入。原 NG 仍存在且尺寸匹配时显示原图选区，否则显示内嵌素材，可重新打开 NG 更换素材。路径不作为图像内容校验；源文件被替换会改变结果。

配方和导出 JSON 记录本机来源路径与缺陷图像内容。分享前按实际需要处理这些业务数据。原图只读，程序不需要任何密钥。用户图片、配方、生成结果、构建输出不应提交到源码平台。

## 验证边界

程序测试验证尺寸、灰度/RGB格式、随机复现、区域边界、掩膜一致性、配方恢复和桌面导出流程。`verification/test_only_fixtures` 是人工测试数据，不能作为真实 OK 或实际检测效果的证明。

训练前先按真实物件/批次划分数据；同一 OK 图及衍生图放在同一组。连续近似图也应分组。用独立真实 OK/NG 比较加入合成图前后的误报、漏检；本工具不保证检测精度。

详见 [文档索引](docs/00-索引.md)、[合成实现与数据格式](docs/01-实现与数据格式.md)、[工具箱整合与转换协议](docs/03-工具箱整合.md)。

## 开发与打包

```powershell
python -m unittest discover -s tests -v
python -m pip install -r requirements-build.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
powershell -ExecutionPolicy Bypass -File build.ps1 -Python python
```

运行 `build.ps1` 打包为便携目录。UI 测试会创建清楚标记的测试图像与截图，均在被 Git 忽略的 `verification/` 内。

构建脚本会将 Qt wheel 配套的 VC 运行库放入便携程序的私有目录，避免旧 Python 运行库与新 Qt 混用；不修改系统目录或系统运行库。

### v1.0.1 启动修复

修复 `ImportError: DLL load failed while importing QtCore`：构建机 PATH 中 Poppler 的 `icuuc.dll`（ICU 78，带版本后缀的导出符号）被误打包，覆盖了 Qt 所需的 Windows 系统 ICU 接口。固定打包规格排除未版本化的 Windows ICU DLL，让 Windows 从 System32 加载配套实现。程序目标为具备系统 ICU 的 Windows 10/11，当前仅在本机验证。

构建结束后必须直接运行便携 EXE 验证 Qt 导入、预览、两张测试图导出和掩膜一致性，报告位于 `verification/portable_smoke.json`。验证失败时构建脚本返回错误，不再仅以 PyInstaller 完成作为交付依据。测试数据位于临时目录并自动清理。

### v6.0 工具箱整合

统一窗口、侧边导航、配色、参数和状态反馈。沿用 VT Studio 5.0 原核心与标注保护设置，新增尺寸转换到缺陷合成的明确 OK 底图交接。构建门槛同时覆盖原核心转换、左上角原点、XML 原样复制和模块交接。原 v1 配方 schema 与合成数据格式保持兼容。
