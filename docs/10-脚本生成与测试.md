# VM 脚本生成与离线测试

最后更新：2026-11-12

## 使用流程

工具箱左侧打开“脚本生成与测试”。填写产品名，直接粘贴VM中的整行NGtype，例如“污点-接头-内装折角-导流层缺失”。工具自动按-拆分、Trim并保留顺序，不再逐项建立类型表。为本产品配置独立信号（变量名以Result结尾）和AI标签归一化；目标类型从解析出的下拉列表选择，不重复手填。自动解析不改变VM运行时读取NGtype的方式，也不把类型顺序硬编码进Process。连续/首尾分隔符、重复类型会直接提示。现有映射指向已移除的类型时显示“未匹配”，需选择正确目标或删除该规则，不自动猜测归类。“产品独立信号”和“AI标签归一化”两张表按实际行高及内容行数自动调整高度，最小96、最大380逻辑像素；添加/删除行或打开不同产品配置会自动增高/收缩，达到上限后在表内滚动。代码和变量清单随有效配置更新；配置不完整时停止生成并显示具体原因。

右侧只展示可直接复制的UserScript.cs脚本代码；属性访问器仅在离线测试内部使用，不作为用户复制内容。在“离线测试”输入一帧数据或运行预设回归；程序用Windows .NET Framework 4.x编译器编译本次生成的真实C#代码，再执行离线输入输出替身。结果显示Process返回值及四个输出，不通过Python另写一套判定逻辑。

代码预览使用常见C#深色配色：关键字蓝、控制流紫、类型青、方法浅黄、字符串橙、数字浅绿、注释绿；支持多行注释、逐字/内插/原始字符串和预处理指令的词法着色，并有行号与当前行背景。中文/非BMP字符按Qt的UTF-16坐标定位。高亮只影响显示，不改变复制和保存的源码，也不升级离线编译器的语言版本。配置未改变代码时，复制和刷新保持原滚动位置。

主操作为“复制脚本”，粘贴到VM脚本模块；可选“保存.cs”仅保存单个UserScript.cs供VM文件导入。按“变量清单”手工配置VM输入/输出。没有脚本包、属性文件、CSV或离线宿主导出功能；产品规则JSON仍可保存/打开。

## 变量契约

6.8起，“变量清单”按输入、输出两组显示数量，分界可拖动调整两组高度，列表各自滚动。当前生成脚本的变量名、说明支持双击或F2编辑；用途、VM类型由模板决定，固定五种输入用途和四种输出用途保留。修改同步到C#、内部测试访问器、数组API端口名、测试用例和结果显示；非法/重复/框架保留名称拒绝并恢复原值。产品信号仍为int且以Result结尾，编辑其名字也同步左侧规则和导入USER CODE中的标识符。用户区注释及普通字符串数据不做文本替换。

下表为默认端口名称，可在变量清单中改名。类型不能任意修改，以保持NG判定契约。备注仅供操作人员参考，不进入判断代码。输入与输出的名称必须全局唯一；内部局部变量、类/API名字及C#关键字不能用作端口名。

固定输入始终存在，包括不使用AI的产品：

| 输入 | VM类型 | 用法 |
|---|---|---|
| aiResult | int | 0表示AI异常，1表示正常 |
| NGtype | string | 运行时类型列表，以-分隔；决定输出位顺序 |
| Label_name | string | 绑定AI的ClassLabel(All)；使用GetStringArrayValue整组读取 |
| speed | int | 当前线速 |
| 起始存图速度 | int | speed达到此值时NG_saveImg=1 |
| 产品XXXResult | int | 产品自定义；0异常、1正常，按对应NG类型取或 |

Label_name拼写以用户截图为准，不使用lable_name。VM编辑器中变量类型显示string不代表只能读取一个标签。生成的属性参考文件以string[]接收整组标签；主流程直接调用数组API，不依赖该属性。因此，VM自动生成单字符串属性时也不需要改写自动文件，不能改回拼接串判定。

输出严格为四项，不额外生成ModuRunTime：

| 输出 | 类型 | 值 |
|---|---|---|
| outResult_index | string | 每类型一位，0=NG、1=OK，以竖线连接 |
| NG_name | string | 首个NG类型；配置/分类异常前缀为“分类或配置异常；” |
| NG_imgName | string | (speed)名字_yyyyMMddHHmmss_fff |
| NG_saveImg | int | speed >= 起始存图速度 ? 1 : 0 |

普通独立信号NG并不使Process返回false。Process仅在NGtype空档，或AI异常时标签读取失败/数量非法、标签为空、存在未知标签时返回false。未知标签不自动归入其他类；已知类型的位仍按实际命中计算，因此下游还应检查Process状态与NG_name。

NGtype先按-拆分并Trim，保留空段以便发现配置错误。AI标签逐项Trim，按规则表由上至下执行首条匹配（包含/等于），去空、去重；示例按接头优先，污点或胶滴归入污点。客户端数组缓冲为4096项，结果码不为0、raw=null、count<0或count>raw.Length均算读取失败，4096不是SDK通用上限。

关闭“此产品启用AI类别判定”后，仍声明aiResult和Label_name，但不读取其值来判断NG，不要求上游存在AI模块。仅由独立信号判定；没有对应信号的类型保持OK。未使用的归一化规则可保留，重新启用AI时需保证其目标类型存在。

## 生成代码与保留区

UserScript.cs沿用ScriptMethods、IProcessMethods、Init、Process和TryReadAiLabels结构，兼容本机VM 4.4 SDK所用C#语法。两个保留区为IndependentJudge、LabelNormalize。

“导入用户区域”只提取这两块逻辑，不导入旧框架；支持工具生成的// USER CODE标记、CubeMX块注释标记及用户提供的“用户NG判断代码开始/结束”“用户AI标签归一化开始/结束”标记。标记缺失、重复或顺序错误时拒绝导入。导入后其内容优先于表格生成的判定代码；信号表仍用于声明输入变量，可增删。点击“恢复表格生成”可清除导入覆盖。

产品JSON只保存结构化规则，不保存手工代码。保留区随保存的UserScript.cs保存，需要时重新导入。预设回归的预期值依据结构化配置计算，自定义区域故意改变逻辑时可能显示“不一致”，可用当前帧检查实际行为。

## 复制/保存与VM使用

6.9可选择[SOL自动应用](12-SOL脚本自动应用.md)：打开方案并选定目标模块，由本机VM原生导入、编译和另存校验，无需复制粘贴。以下手工流程仍可使用；其他必需输入的上游关联不能凭变量名自动猜测。

1. 将VM使用的NGtype整行粘贴到工具，配置本产品独立信号及标签规则。
2. 点击“复制脚本”粘贴到VM脚本模块，或用“保存.cs”后在VM导入该文件。
3. 在VM界面按“变量清单”手工建立输入与四项输出并关联上游数据。
4. 在VM中编译、测试实际一帧；离线测试不代替现场端口绑定和运行确认。

单个.cs文件使用UTF-8 BOM保存，不夹带UserProperty.cs、SDK DLL或离线API替身。内部属性参考仅供测试编译使用；VM按手工配置自动生成其属性，无需额外抄写属性代码。本机真实SDK编译检查只证明接口和语法兼容，不证明生产方案的端口关联或部署已经生效。

## AI / CLI

产品配置schema仍为vt-script-product/1，增加可选ports和variable_notes。ports用默认用途名作为键、实际端口名作为值，例如`{"Label_name":"检测标签","outResult_index":"检测位串"}`；未设置的项沿用默认名称。variable_notes用默认用途名或`signal:实际信号名`作为键，说明最长300字。旧配置不必添加这些字段。启用改名后，CLI cases中的固定输入键、results.outputs中的输出键使用实际端口名；label_count、label_null、label_read_status仍为测试控制键。复制、保存和CLI共用同一配置验证与生成器。

“打开SOL”可自动读取各流程脚本模块的原始变量，详见[SOL变量读取](11-SOL变量读取.md)。当前生成脚本和SOL参考清单通过顶部来源切换；原始SOL参考不直接编辑。

含ports别名的配置需要6.8或更高版本；旧版本不会应用这些改名。旧配置在6.8继续使用默认名称。

保持原CLI的UTF-8 JSON结果封装和退出码。示例：

```powershell
VTStudioCLI.exe script-template --output product.json
VTStudioCLI.exe script-code --config product.json --output UserScript.cs
VTStudioCLI.exe script-test --config product.json --regression
VTStudioCLI.exe script-test --config product.json --cases cases.json
```

script-template可省略--output，此时配置在JSON结果data中；指定--output会另存可直接供--config读取的原始配置，不覆盖旧文件。script-code在data中返回code及variables作为复制/手工配置参考；可选--output仅保存一个新的.cs文件，不覆盖旧文件。两项命令可用--preserve-from UserScript.cs保留旧用户区。script-test的--cases与--regression互斥，用例列表每次1～256项。可用示例examples/vm_script_product.json及examples/vm_script_cases.json。

用例含固定输入、各产品信号，可额外提供label_read_status、label_count、label_null模拟API边界。缺省值来自产品正常帧；32位整数及标签数组结构在执行前校验。测试编译/执行各有30秒超时，临时文件用后清理。返回execution=compiled-csharp-offline-double，results记录process_return、四项outputs及label_read_calls。

当前帧即使Process=false，只要成功执行测试，CLI仍返回0且ok=true；业务结果看process_return。预设回归存在预期不一致时退出1；编译失败、运行失败和非法配置退出1；参数错误退出2。配置、脚本和用例文件限制1MB。

本模块不接外部AI服务；“AI生成”指根据配置确定性生成代码。生成/导出不要求安装VM；离线编译测试要求Windows .NET Framework 4.x自带csc.exe，实际VM导入还需相应版本和端口绑定。
