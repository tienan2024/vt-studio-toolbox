# 相机参数计算与设置

最后更新：2026-11-13

当前实现7.5.0。默认按“材料→视野→图高→Z周期整数倍频”规划，7.4的按实测走料匹配Y精度保留在专业标定中。计算结果不作为实体相机采集及无拉伸的现场证明。

## 操作流程

选择完整相机型号，程序自动带入并锁定原生分辨率、像元和固定镜头：CL024黑白/彩色为2K、7μm、KF1228/12mm；CL042黑白/彩色为4K、7μm、AF2524M-M42/25mm；CS050 V5黑白/彩色为2448×2048、3.45μm、HF0628/6mm。不猜Bayer排列，彩色格式保持现场值。原生行数2/3不等于线扫输出图高。

主页面分为材料与视野、编码器与图高、采集触发。材料页输入宽W、长L、横向总余量百分比（左右合计）；可由材料宽度反算工作距离，或输入工作距离反推视野及实际余量。编码器页输入P/R、有效计数倍率、每帧间隔圈数，查看或调整图高与最少空档；预分频/倍频/后分频在自动模式只读。面阵隐藏编码器页及行触发。

数字IO、专业标定及成像位于更多参数。小窗口优先完整显示参数和结果，覆盖示意在较大窗口显示；图内背景与周期未采集空档分别命名，不混用。四个工具继续共用styled_controls.py的输入、下拉、数字按钮和禁用态。

## 默认计算模型与验收示例

全幅横向视野 FOV=W×(1+Y/100)，横向精度dx=FOV/N。新流程使用传感器全宽N，不通过缩小ROI冒充视野改变；手动ROI不足时阻止写入。快速估算WD=dx×f/(p/1000)，其中p单位μm、f及WD单位mm。

线扫按方形像素规划dy=dx；产品最少行数=ceil(L/dx)。建议Height按height_rounding（默认100行）向上取整，再对齐设备Height步长，也可手动输入3800或3900等值。取图高度不得少于产品和明确留白所需行数。

输入计数B=P/R×有效计数倍率×每帧间隔编码器圈数。默认PreDivider=PostDivider=1，选择最小可用整数Multiplier，使B×Multiplier至少覆盖Height+cycle_idle_lines（默认100，必须大于0）。连接后遵循Multiplier的min/max/inc；设备不支持预/后分频为1或倍频不足时明确失败，不擅自换成分数倍率。空档=保守向下取整的周期行触发数−Height。

用户示例：W=200mm、L=400mm、Y=10%、CL024/12mm、N=2048、p=7μm、1000P/R、×1、每Z周期一圈：

| 输出 | 结果 |
|---|---|
| 视野 | 220mm |
| 快速估算工作距离 | 184.151785714mm，界面显示184.152mm |
| dx及规划dy | 0.107421875mm/px |
| 产品最少行数 | 3724 |
| 默认建议Width×Height | 2048×3800 |
| 预分/倍频/后分 | 1/4/1 |
| Z周期总行触发数 | 4000 |
| 图内背景 / 周期空档 | 76行 / 200行 |

手动Height=3900时仍为1/4/1，背景176行、空档100行。设为4000时自动提高倍率以保留空档，不能将4000图高与4000周期行数直接当安全方案。若有效计数为×2/×4，本例倍率为2/1；倍率必须以设备实际有效计数核实，不把此统计选项冒充硬件计数模式已修改。

## 无拉伸与标定边界

周期收到足够行触发只证明容量够用，不证明物理dy=dx。规划要实现方形像素，本例Z周期对应走料应为4000×0.107421875=429.6875mm；这不是要求输入产品间距，也不是已测得的工位数据。

专业标定可填cycle_travel_mm（实测Z周期走料，0表示未知）。实际dy=S/C，并估算实际产品行数。实测行数超过Height或实际dy与dx差异超过frequency_tolerance_percent时阻止写入。若本例实测S=400mm，则实际dy=0.1、产品约4000行，3800/3900都会裁掉产品；程序必须报出该问题。未标定时显示Y为规划值，不显示零误差冒充已证明无拉伸。

主平面及实测视野方式保留：thin_lens令u=WD+主平面偏移，dx=p(mm)×(u−f)/f，反算WD=f×(1+dx/p)−偏移。未知主平面填0仍为近轴模型；法兰后焦不能作为主平面偏移。快速模式保留远距公式，用户示例184mm对应快速模式，薄透镜模式为约196.152mm。畸变、对焦及实物距离须实测校准。

原有FOV/已知精度、产品长度÷原始占用行数标定以及按每圈走料求Y精度的算法在原计算配置/专业标定中可用，输入必须基于未缩放图像。不能把周期走料长度、产品长度、图高或产品间距互相替代。

## 频率、触发与设备写入

稳定匀速预计外部行频=最高产能/60×C；平均图像行输出=最高产能/60×Height。两者分开，不拿平均图像输出当采集期实际行频。实际峰值、曝光及带宽按设备读回核对。AcquisitionLineRateEnable=False不写AcquisitionLineRate，也不把其未启用值作为真实行周期。

离线整数推荐使用1～256参考范围并标记未核对设备；自动写入需要三个倍分频节点范围完整可读。按走料匹配模式仍使用有界整数搜索及Y误差容差；cycle默认策略不按“误差最小”凑成3.724之类比例，而是凑到满足图高及空档的整数倍率。周期平均值非整数时提示核对计数相位，不宣称busy/缓存/触发无丢失已验证。

帧触发开始后采满Height结束一张图，Continuous/单触发一帧/Timed及原依赖写入顺序保留。下位机负责帧相位，工具不写板、不追加图像白边。示意图居中不表示现场产品位置已执行。

## 配置及兼容性

schema仍为vt-camera-config/2。新增framing_source（material/distance/legacy）、horizontal_margin_percent、frequency_strategy（cycle/pitch）、height_rounding、cycle_idle_lines、cycle_travel_mm；旧文件缺省legacy/pitch，按原公式计算，不静默将旧参数换成新流程。schema1仍执行旧留白合并与Y来源legacy确认。新GUI及camera-template/camera-plan无配置时使用workflow_settings示例（200×400/10%/2K彩色/12mm/1000P-R），不是现场实测数据。

计划vt-camera-plan/1及配置记录输入和最终整数因子，metrics新增cycle_idle_available、cycle_travel_for_square_mm、actual_y_mm_per_px、actual_product_height_lines、horizontal_margin_percent_actual。y_sampling_error_percent在cycle模式为null，不能据此声称实际误差0。lines_per_product仍仅为C的旧兼容别名。

设备读取会取得各LineSelector上下文的LineSource支持项以及触发输入支持项，操作后恢复选择器，不为获取列表改LineMode。若某输入模式下信号源不可读，明确使用待核对的参考选项；后续对比仍按设备实际能力校验。已加载但不受支持的旧值保留以便操作者修正，不静默换值。中文/English切换参数名称和已知枚举显示文字，SDK字符串及JSON保存值保持不变；未知厂商枚举保留原文。未连接设备时仅提供需求摘录中的曝光开始有效/软触发有效作为参考，不宣称为设备完整支持列表。

相机能力由设备读回；配置JSON可保存完整工位设置，换产品复用标定。所有四页使用同一共享控件模块styled_controls.py；主表单36px，表格或窄字段28px。保留原有NoButtons输入方式、模型/delegate、编辑、信号和自动背景参考禁用语义。动态新控件也初始化，数字字段及内嵌编辑框避免重复边框。

枚举→选择序列号/传输类型→读取尺寸→对比→查看差异→写入UserSet1。修改配置或目标使对比失效；设备任务期间锁定配置文件菜单/SDK目录入口。读取/对比报告另采集帧/行TriggerDelay、LineDelayEnable、帧/行缓存、FrameTimeout及残帧策略、TDI/Binning。附加项仅读回，不猜单位强写；FrameTimeoutTime在型号描述中存在单位文字冲突，留给设备/型号资料确认。相机延迟不等于下位机相位，避免未知叠加。

对比以后，计划节点、用户集状态或可读延迟/缓存/超时状态改变会拒绝过期写入；动态频率值变化不会被误判为静态配置修改。选择器读写均按上下文并恢复。只读附加状态出现在读取/执行记录与导出JSON中。

## 有序写入和恢复

不抢占/停止其他程序采集，不运行视觉流程。写入先关闭帧/行触发、保存全部可读计划原值、复位ROI偏移，再配置模式、IO、格式及ROI。依据同型号GenICam约束，先配置并开启LineStart，再在LineStart选择器上下文设置Timed和曝光，最后开启帧触发。BurstFrameCount在帧选择器上下文设置；不在错误选择器下强写依赖节点。

各项读回后核对允许行频→UserSet1 Save→Load→再次核对→设置默认用户集并读回。Save开始前失败尽力恢复格式、尺寸、依赖模式及原触发状态；曝光恢复也考虑LineStart依赖。切换模式前不可读或恢复失败的原值明确列入未核实项，不能宣称完整恢复。Save开始后失败报告用户集可能变化，不能声称完整回滚。

## 配置与计划契约

当前schema为vt-camera-config/2。新增line_y_source、calibration_length_mm、calibration_rows、image_horizontal_margin_mm、image_vertical_margin_mm；移除product_pitch_mm、image_top_margin_mm、image_bottom_margin_mm、allow_overheight。schema1导入时合并原上下留白，旧节距/C仅作历史Y换算值并标记legacy，操作者必须在工位标定选择新的Y来源确认后才可写。面阵旧配置按原光学含义迁移。保存统一为schema2，不静默把旧节距换成新物理含义。

7.3在schema2增加可选optics_direction，省略时默认wd_to_precision，兼容此前schema2文件；不修改原字段含义。camera-inspect结果增加output_source_choices和trigger_io_choices；每路信号源包含可读状态、枚举列表、当前值和可写状态，或不可读原因。

计划vt-camera-plan/1内嵌schema2设置，metrics提供line_triggers_per_cycle、product_height_lines、vertical_margin_lines、background_height_lines、average_image_line_rate_hz。lines_per_product仅保留为C的旧兼容别名，新界面不再把它叫产品图像行数。比较/写入JSON保留原schema并增加observed_trigger_state、observed_before_save、observed_after_reload等附加状态。

## SDK、MFS与CLI

已补充D:/MVS安装目录发现，枚举包含虚拟GigE/USB3（SDK类型0x10/0x20）。物理设备UID沿用GigE:序列号、USB3:序列号；虚拟设备使用VirtualGigE:序列号、VirtualUSB3:序列号，并增加virtual布尔字段，避免同序列号混淆。独立GenTL采集卡传输类型未接入，不按GigE结构强转。使用虚拟设备时由用户以管理员身份启动程序，工具不自动提权或修改目录权限。

虚拟功能的边界以本机MVS帮助“添加虚拟设备”（GUID-2148F185-ADF7-4A98-A469-66AE5F133AEF.html）为准：虚拟相机主要支持宽高、像素格式，触发源仅软触发或采集卡触发；虚拟采集卡也只有部分出图、软触发/快速软触发、定时器配置可用。不为通过测试跳过原对比校验，不把虚拟设备支持情况当成外部IO、编码器或UserSet持久化证明。

camera_model.py纯计算；camera_sdk.py加载本机MVS x64 Python封装/运行库；camera_transaction.py比较、附加读取、有序写入及恢复；camera_ui.py第四页。厂商SDK/DLL不随包分发。VT_MVS_DIR指定封装位置，VT_MVS_RUNTIME指定运行库；冻结版从安装目录绝对预加载DLL及本进程依赖路径，切换SDK目录需重启。

JSON/MFS上限1MB；CLI拒绝覆盖已有输出。MFS只解析已支持ROI、曝光/增益、倍分频、格式和部分触发字段到模板，不执行文件，不使用全量FeatureLoad，不声称完整恢复原MFS或推断外部编码器P/R。单帧/Timed等由工具模板设定；原配置未摘录的延迟/缓存等从目标设备读取。网络IP/包长等保持现场设置。

CLI入口不变：camera-template、camera-plan、camera-info、camera-inspect、camera-compare、camera-write。设备命令支持--sdk-dir。camera-write接受有效对比原始JSON，重新核对设备和当前状态；真实写入及UserSet流程须操作员执行。无设备的camera-info成功返回空列表；纯计算/配置/UI测试不作为现场成像、触发无丢失或断电保持证明。
