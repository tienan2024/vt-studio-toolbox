# 多 NG 素材池与合理匹配

最后更新：2026-10-27

## 操作

1. 多选OK底图，导入同款、位置对应、同类缺陷的NG图片或当前层文件夹。
2. 点击NG列表逐张圈选素材、另框生成范围。切换NG时自动保存和恢复各自状态，列表显示待圈选/已圈选。新NG范围初始为全图，可在NG上另框或在OK上微调。
3. 预览当前OK，查看提示中实际选用的NG来源。预览从全部已圈选素材中随机匹配，不要求使用列表当前项。绿色预览框对应实际选中的NG范围，左侧范围说明对应列表当前NG。
4. 在批量导出区设置“每张OK数量”或“本批生成总数”。每张方式合计为OK数量×每张数量；总数方式严格输出填写张数并均匀分配。未圈选NG不参与；多选列表项用于移除，不限制素材池。每张结果迁移一个缺陷。详见 [数量设置](07-批量生成数量.md)。
5. 保存素材池配方，恢复全部已圈选NG及范围；未圈选NG的路径和已框范围也保存，以便继续处理。最多200张NG，配方总大小不超过340MB。

右键按住拖动平移所有画布，滚轮缩放。多边形右键单击或Enter收尾；右键拖动不会收尾或改动选区，中键不再平移。小窗口可滚动左侧参数栏，右侧NG工具栏也可直接切换“框选生成范围”。

## 匹配规则

由操作者保证同款、相同材料布局和统一缺陷类别。程序不做产品识别、材料语义分类或训练效果判断。不同产品、材料布局、缺陷类别请分池。

每个样本按种子打乱NG候选顺序，依次检查：

- 与当前OK同为L或同为RGB，不自动转颜色模式。
- 使用该NG独立的归一化生成范围，映射到该OK。
- 缩放和旋转后的整个素材框能放进范围；实际像素产生有效变化。

不满足的候选跳过，使用第一个可生成的候选。因此池可以含灰度和RGB，自动按当前OK筛选；“合理”限于上述规则，材料相似性仍由操作者确认。固定种子、素材顺序和原图内容不变时结果可复现。

任何分配到生成数量的OK在预检中没有可用NG时，整个任务报错且不创建批次，不静默跳过、不放宽范围。总数小于OK数时，按列表顺序仅使用前几张OK，零分配项不参与预检。后续样本仍可能因具体随机变换或文件错误失败，按failed状态保留已完成数据；取消同样保留已完成清单。

## 配方与结果契约

新配方schema为 `vt-defect-pool/1`，匹配策略为 `same_mode_roi_fit_seeded`：

6.5可在每项和pending_ng中携带可选rois数组，空数组/缺失保留旧roi行为；最多64框。选择素材后还会随机尝试可用框，必须完整放入单个框，禁止用多个框的大外接范围代替。各图默认同时输出VT XML矩形标注，PNG仍保留精细掩膜。

- settings：共享缩放/强度/类别/随机种子/数量等参数。池匹配以每项roi为准，不使用共享settings.roi覆盖。
- entries：每项含id、name、roi和asset；asset沿用原无损素材、L掩膜、背景参考及来源字段。
- pending_ng：每项含path、id、roi；尚未圈选，不参与生成。
- ok_paths：底图路径。原NG丢失时内嵌素材可继续生成；不能在素材裁图上重新取缺陷或设置完整NG坐标范围。

旧 `vt-defect-lab/1` 单素材配方自动适配成单项池，原engine单素材API保留。新池配方需6.3或更高版本，旧工具不能读取。

每个批次含images/、masks/、annotations/、assets/、recipe.json、manifest.jsonl和summary.json。标注仍使用原通用单图schema，额外记录pool_entry_id、pool_entry_name、matching_policy和source_roi_normalized；source_defect为实际使用NG的来源。allowed_roi_xyxy是实际允许像素范围，placement_xyxy完整落在范围内。

summary以池schema记录状态、数量、pool_entries和donor_usage（各ID使用次数）。取消/失败时统计仅计入已写入manifest的完成样本。GUI素材池、CLI多素材以及CLI读取配方都使用同一匹配代码；CLI单独 `--asset` 仍保留原单素材输出布局。
