# AI 命令行接口

最后更新：2026-10-27

## 入口与机器契约

便携目录内 `VTStudioCLI.exe` 是正式无界面入口，与 GUI 共用 `_internal`、转换核心及合成引擎。无需启动桌面、点击控件、安装 Python、联网或 GPU。源码入口为 `python cli.py`。

普通命令 stdout 只输出一个 UTF-8 JSON 对象；`--help` 与 `--version` 是文本。可选 `--progress` 将 JSON 行进度写入 stderr，不污染 stdout。`--json-out 新文件.json` 额外保存最终JSON，拒绝覆盖。全局参数放在子命令前。

```json
{"schema":"vt-toolbox-cli/1","ok":true,"command":"info","exit_code":0,"data":{}}
```

失败包含 `ok=false`、`error`、`error_type`，无交互确认框。部分失败和取消仍返回批次位置与统计。退出码：0成功，1参数值/文件/处理错误，2命令语法错误，3转换有跳过或失败，130取消。

AI 可先执行 `info`、`schema`，读取命令、参数范围、默认值和退出码。所有操作仅处理本机文件，不启动海康训练、不上传图像、不改写原图。

## 调用示例

在完整便携目录运行，下列路径请替换为真实路径：

```powershell
.\VTStudioCLI.exe info
.\VTStudioCLI.exe schema
.\VTStudioCLI.exe inspect "D:\images\OK\sample.bmp"

.\VTStudioCLI.exe convert --input "D:\images\OK" --output "D:\images\converted" --width 3200 --height 3960 --fill white

.\VTStudioCLI.exe extract-asset --ng "D:\images\NG.bmp" --rect "100,200,300,450" --output "D:\recipes\stain.json"

.\VTStudioCLI.exe synthesize --asset "D:\recipes\stain.json" --input-folder "D:\images\OK" --output "D:\images\synthetic" --count 10 --seed 42 --class-name "脏污"

.\VTStudioCLI.exe validate-recipe "D:\recipes\recipe.json"
.\VTStudioCLI.exe synthesize --recipe "D:\recipes\recipe.json" --output "D:\images\synthetic" --count 10

.\VTStudioCLI.exe --json-out "D:\reports\new-report.json" --progress synthesize --recipe "D:\recipes\recipe.json" --output "D:\images\synthetic"
```

## 参数语义

| 命令 | 输入与约束 |
|---|---|
| info | 版本、能力、原核心指纹和命令清单；验证核心完整性 |
| schema | 当前CLI机器可读契约 |
| inspect image | 宽高、原模式、格式、是否支持合成；兼容时返回 effective_mode（L/RGB） |
| convert | input/output文件夹，目标width/height像素；原点固定左上，fill为black或white |
| extract-asset | ng 为 L 或 RGB 原图；rect或polygon二选一；output为不存在的素材JSON |
| synthesize | recipe或asset二选一；ok文件列表或input-folder二选一，也可沿用配方路径；output为批次根目录 |
| validate-recipe | 检查结构、素材和参数，单独列出底图路径存在性，不代表现场数据有效 |

`--rect` 为原图像素 `left,top,right,bottom`，零基、右下不包含。示例宽200、高250。`--polygon` 为 `x,y;x,y;x,y;...`，至少3点。CLI拒绝越界坐标，不自动识别缺陷。

合成可覆盖配方参数：`--count`（每张OK生成1～1000张）、`--seed`、`--mode darken|texture`、`--class-name`、`--scale-min/max`、`--strength-min/max`、`--rotation`（±角度）、`--feather`（输出像素）、`--reference-gray`、`--roi-normalized`。这里 min/max 简写指两个独立选项，如 `--scale-min` 与 `--scale-max`。未指定的参数沿用配方或 Settings 默认值。

`--roi-normalized` 是0～1比例的 left,top,right,bottom，按底图尺寸映射，不能传像素值。缩放倍率相对素材，不缩放底图。执行 `schema` 获取完整范围。

转换默认包含子目录、原样复制XML；使用 `--no-recursive`、`--no-copy-xml` 关闭。`--allow-annotation-clip` 默认关闭，沿用原核心保护规则。递归同名图或同名配套XML拒绝运行。

Ctrl+C请求取消，完成当前样本后停止并保留数据。素材schema为 `vt-defect-asset/1`，内嵌无损PNG和掩膜；旧单素材配方为 `vt-defect-lab/1`，6.3 GUI素材池配方为 `vt-defect-pool/1`。

## 6.1 RGB 支持

上述命令无需新增开关，自动保留 L 灰度或 RGB 颜色模式。RGB 每通道8位，合成结果为24位BMP；掩膜仍为单通道L，任意颜色通道发生变化即标记255。OK 与 NG 素材须同模式，混用时返回退出码1且不创建批次。索引图展开为L/RGB；RGBA、透明图和16位输入明确拒绝。

RGB 暗缺陷自动按 R/G/B 通道估计背景，纹理粘贴保留素材颜色。`--reference-gray 0` 使用自动估计，手动1～255时三个通道共享该值。亮色和异色缺陷可使用 `--mode texture`。

`info` 新增 `defect_input_modes`，`schema` 新增 `color_policy`；素材提取结果新增 `image_mode` 和 `reference_rgb`，配方检查新增 `asset_mode` 和 `reference_rgb`。灰度场景该RGB字段为null。JSON字段为兼容增量；旧灰度配方仍可加载，RGB配方需6.1或更高版本。

## 6.3 同款多NG素材池

`synthesize --recipe GUI素材池配方.json` 读取全部已圈选素材并保留各自范围。`--assets a.json b.json` 可直接组成素材池；与 `--asset`、`--recipe` 互斥。`extract-asset`新增可选 `--roi-normalized`，保存此NG的生成范围到素材JSON的roi_normalized字段，默认全图；单素材 `--asset` 也读取该范围。

```powershell
.\VTStudioCLI.exe extract-asset --ng "D:\NG\a.bmp" --rect "100,100,200,200" --roi-normalized "0.1,0.2,0.8,0.9" --output "D:\recipes\a.json"
.\VTStudioCLI.exe synthesize --assets "D:\recipes\a.json" "D:\recipes\b.json" --input-folder "D:\OK" --output "D:\synthetic" --count 10 --seed 42
.\VTStudioCLI.exe synthesize --recipe "D:\synthetic\run_x\recipe.json" --output "D:\another-run"
```

池批次schema为 `vt-defect-pool/1`，来源、单项ROI和用量可追溯。`--roi-normalized`用于synthesize时会显式覆盖全部池条目的范围；未提供则沿用各自范围。每张OK生成count张，不是OK×NG的全组合。无可用NG时返回1且预检不创建批次。固定种子、条目顺序及输入可复现；原NG图丢失不影响内嵌素材生成。

`validate-recipe`仍兼容原单素材字段，另返回pool_entries、entries（ID/名称/模式/范围/来源）、matching_policy和pending_ng_paths。`info`新增multi_ng_pool；`schema`新增pool_policy。旧单素材配方仍支持，新池配方需6.3或更高版本。详见 [匹配与数据格式](06-多NG素材池.md)。

## 6.4 精确批量总数

`synthesize --total 100` 指定本批合计100张；`--count 5` 仍指定每张OK生成5张，二者互斥。总数范围1～100000，每张范围1～1000。不指定时沿用配方；显式--count会关闭配方的总数方式，显式--total会改用总数方式。单素材、多素材和GUI池配方均支持。

```powershell
.\VTStudioCLI.exe synthesize --recipe "D:\recipes\pool.json" --output "D:\synthetic" --total 100
```

总数按OK输入顺序均匀分配，余数优先前面的OK；只读取、匹配和预检分配数大于0的底图。summary返回quantity_mode和planned_ok_counts，total是计划总数，completed是实际完成。配方保存settings.total_samples正值（需6.4以上）；旧配方默认0=按每张数量，按每张保存仍省略新字段。详见 [批量数量](07-批量生成数量.md)。

6.2旧单素材配方的范围位于settings.roi，6.3池配方位于各entry.roi，均是0～1比例。AI用 `synthesize --recipe` 沿用范围，或用 `--roi-normalized` 覆盖。无需提供NG原图；整个素材须放在范围内，过小会返回退出码1。参考 [NG生成范围](05-NG生成范围.md)。

## 6.5 多个范围与VT XML

extract-asset和synthesize均接受--roi-regions，格式为分号分隔的归一化矩形，例如 "0.05,0.1,0.3,0.4;0.7,0.6,0.95,0.9"，最多64个，不能与--roi-normalized同时使用。素材JSON保存roi_regions_normalized，池配方保存每项rois，旧单框字段仍可读取。synthesize显式指定会替换全部池素材的范围；不指定则沿用各自范围。

缺陷必须完整放在其中一个可用框内，不能跨越框间空白；记录allowed_rois_xyxy、selected_roi_index和实际使用的allowed_roi_xyxy。validate-recipe返回每项roi_regions_normalized。

--xml vt-flaw为默认的原生缺陷矩形XML，--xml none关闭。XML与BMP同名并放在images/，record含vt_xml与vt_xml_profile。精细掩膜仍为PNG；该XML不代表逐像素分割。默认自动开启，配方可显式保存export_vt_xml=false，命令行选项会覆盖配方。

## GUI兼容入口与验证

GUI EXE接受 `--cli`，但无控制台入口必须配合 `--json-out` 并等待进程结束。自动化优先使用真正的控制台程序 `VTStudioCLI.exe`。新版目录为release/6.5.0/VTStudioToolbox，具体XML字段与验证范围见[VT XML](09-VT_XML导出.md)。

`tests/test_cli.py` 用真实子进程覆盖命令发现、JSON封装、图像检查、原像素转换、素材到批次、GUI配方复用、进度隔离、错误码、报告拒绝覆盖和部分失败。设置 `VT_TOOLBOX_CLI_BINARY` 为便携CLI绝对路径，可用同一测试验证打包后二进制。
