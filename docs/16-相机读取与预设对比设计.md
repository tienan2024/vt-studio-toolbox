# 相机读取与预设对比设计

最后更新：2026-11-17

状态：7.14实现读取与写入分离，7.15.1自动匹配所选设备机型，7.16预设按完整机型分库，7.18.3将设备预设对比收敛到有相机读回来源的字段。实体相机读写及成像效果尚待现场验证；本机验证范围见[验证记录](02-验证记录.md)。

## 要解决的问题

7.13的“读取设备尺寸”主要读取几何尺寸、支持项及部分触发状态，还会把匹配的机型和PixelFormat带入当前表单。“对比相机参数”比较设备与calculate生成的写入计划，对比结果藏在参数明细中。7.14分离原始预设对比和最终写入计划，直接显示两者入口。

流程为：选相机 → 读取并对比 → 查看与预设的差异 → 载入或调整当前设置 → 校验并生成写入计划 → 写入相机并保存。最终写入计算后的有效参数。

## 三份数据分别保留

| 数据 | 来源 | 规则 |
|---|---|---|
| 设备快照 | 本次SDK读回 | 记录设备UID、型号、序列号、读取时间、各选择器上下文的值与能力；界面只读 |
| 所选预设 | 当前完整机型、当前页的两组可命名预设 | 仅比较有SDK节点或硬件身份/几何来源的原始保存值；这些字段未保存时显示“未设置”，不拿当前表单补齐后冒充预设，也不跨机型回退 |
| 当前设置/计算目标 | 左侧表单与工位计算 | 用于生成写入计划；硬件身份随所选设备同步，读取保留工位和成像输入，预设变化不自动应用 |

“载入当前设置”只填入本页预设，不写设备。7.15.1移除“采用设备机型”：枚举/切换设备时自动同步型号及已知型号的传感器、像元和固定镜头，读取后用设备全幅几何尺寸复核。重新枚举保留仍在线的原设备UID。连接期间机型下拉只读，载入预设或文件也保留所选硬件。材料、走料、标定、曝光、Gain、PixelFormat和触发输入不因读取而采用设备当前值；光学结果按新硬件重算，材料/距离锁定保留，仅解除不相容的硬件数值锁定。未知型号显示实际名称，首次匹配清空旧像元/焦距，后续保留手工值。完整型号仅规范空格和大小写，不将缺少V5的型号自动视为V5。写入计划继续执行型号、传感器和能力校验。

### 预设对比

表头明确显示正在比较的“完整型号 · 参数页 · 可读预设名称”。默认跟随左侧当前页，另提供“全部参数”和“仅看差异”筛选。每个完整机型的每页有两组，名称可改；切换机型恢复原先各页的选择，全部模式仅组合该机型各页当前所选。载入、保存、重命名和对比共用该型号上下文，042的预设不会在024下显示或载入。不同序列号的同型号设备共享两组，未知型号另建空预设。存储、初值和旧通用预设归档见13。

### 写入计划

单独显示“参数/上下文、设备当前值、当前待写值、校验结果”。这张表继续沿用现有compare/apply_comparison的能力、依赖顺序、旧状态指纹、UserSet保存和重载校验。

预设对比不会自动修改相机。先将希望使用的值明确带入当前设置，再生成完整写入计划；不新增绕过现有依赖校验的逐行直接写入入口。通过校验后“写入相机并保存”才可用，写入后保存/加载UserSet1、再次读回并设为默认。操作完成或失败会使本次计划失效，修改参数会清空旧计划表。

## 读取和比较规则

- 读取与预设对比不依赖材料计算有效。周期走料未知时，也应能比较IO、触发、曝光和ROI；实际采样与写入计划仍按原有规则校验。
- Snapshot读回与表单导入分开。读取刷新设备快照、硬件身份、支持项和差异，保留正在编辑的PixelFormat等成像值，避免消掉待比较的差异。
- 比较使用SDK原始枚举值；中英文只影响显示。浮点比较考虑设备步长或合理数值容差，避免显示精度导致虚假差异。
- 快照是有时间的读数，不冒充实时状态。切换设备需重新读取；切换预设可用现有快照重新比较，但写入前仍要重新核对当前设备和状态。
- 参数按分组展示。读取失败或未读到的值不能填成0，也不能认作“与预设一致”。

状态区分：一致、不同、预设未设置、设备不支持、当前条件不可读、读取失败、预设超范围、预设机型不匹配。工位输入及没有明确预设目标的自动/未启用项不进入本表和差异计数，实际写值以计划为准。不同/超范围/机型不匹配用橙色；详细上下文和失败原因可悬停查看。即使两个机型的增益值相同，归属不同也不会认作一致。

## 必须保留选择器上下文

同名节点按“选择器+节点”区分，继续复用node_id的身份规则。例如：

| 业务含义 | 节点身份 |
|---|---|
| 帧触发源 | TriggerSelector=FrameBurstStart / TriggerSource |
| 行触发源 | TriggerSelector=LineStart / TriggerSource |
| Line0输出信号 | LineSelector=Line0 / LineSource |
| Line4输出信号 | LineSelector=Line4 / LineSource |

为读取可临时切换选择器，结束后恢复；不为“看清参数”修改LineMode、TriggerMode、ExposureMode或其他成像配置。依赖当前模式而不可读的项目标注原因，留到写入计划的依赖校验阶段处理。

输出1/2是工具中的逻辑分组，设备端需落到各自Line上下文比较。不能将设备当前LineSelector位置误当作它唯一使用的输出线。

## 不应从相机读取的工位参数

材料长宽、横纵余量、机械工作距离、镜头实测标定、编码器P/R、每圈走料、周期实际走料、要求方形像素和容差等，没有相机节点读回来源，不再进入设备预设对比。它们继续保存在原工位预设及配置中、显示在原输入表单，参与原有计算与最终写入校验；本次不改变存储、公式或写入规则。

ROI、曝光、增益、触发源/边沿、编码器源、倍分频、输出Line模式/来源等才按实际支持的SDK节点比较。型号、尺寸和能力也应显示来源；镜头像元参考值不能冒充设备实测标定。

7.18.3采集触发预设还包含EncoderSourceB、EncoderOutputMode、EncoderCounterMode、InputSource和SignalAlignment的独立设备目标。编码器方向和分频器对准沿只比较各自节点，不拿软件edge_factor当作硬件倍率。显式converter_alignment存在时，line_edge仅映射LineStart.TriggerActivation，避免在两个字段重复比较同一SignalAlignment；旧预设未设置时仍沿用line_edge的历史映射。转换器直接使用Line输入时，按该Line比较电气格式与消抖，不比较未使用的编码器模块；面阵不应用线扫触发预设。配置默认和兼容规则见13。

## 数据与验证边界

camera_snapshot.py维护工具相关节点表，读取成像、倍分频、编码器、帧/行触发及各物理Line上下文；不宣称覆盖厂商全部节点。读取结果为vt-camera-snapshot/1：device、read_at、geometry、rows、selector_capabilities；每行包含entry、value、capability、status、detail。选择器自身不可读时保留原因，不误判其整个分组为设备不支持。camera-inspect将其作为snapshot附加字段返回，保留原字段。

预设页保存记录时导出vt-camera-preset-comparison/1：snapshot、selected_presets、rows；7.16附加顶层model，各页selected_presets含slot、model、可读name及values。7.18.3保持字段及schema，收窄设备比较内容：rows只有有设备来源的字段；values仅保留这些行实际使用的原始预设字段，以及frame_selector、output0/4_line和output0/4_enabled等必要接线/分组上下文，不附带工位输入或未比较的自动计算目标。工位完整预设仍使用原预设存储和配置文件，不以此设备比较记录代替。该记录与最终camera-comparison用途不同，不能直接提交写入接口。相机配置schema2及原比较/写入schema不变。

本机以模拟节点验证自动匹配硬件、保留工位/成像草稿及材料固定状态、文件不能替换所选机型、未知型号不猜版本、同名节点按上下文区分、选择器恢复、不可读/不支持/未设置不会当作一致、计算输入不完整仍可只读对比、参数变化使写入计划失效，以及原写入事务保存/加载用户集。实体测试电脑的读取及实际写入仍待复测，不把模拟结果当成现场完成。

7.18.3针对性检查覆盖数据层工位字段过滤、自动目标排除、原预设不变、保留来源/选择器、无材料/走料仍可比较，以及实际Qt表格/差异计数/导出JSON一致和工位页空状态。检查日志为outputs/v7183/camera_compare_tests.log；未操作实体设备。
