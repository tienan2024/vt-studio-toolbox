# SOL 脚本自动应用

最后更新：2026-11-17

## 使用

7.17自动寻找VM目录：依次校验VT_VM_APPLICATIONS、本机记住的目录、注册表安装位置，再有界搜索C/D根目录及Program Files、Program Files (x86)、HIKROBOT、VM、VisionMaster目录；最多向下4层、检查3000个目录，跳过Windows/Users/数据缓存等目录和可识别的链接，不扫描整盘文件。每个候选仍须通过完整x64 SDK文件校验。手动选过的有效目录在确认应用时写入%LOCALAPPDATA%/VTStudioToolbox/vm-install.json，仅保存applications路径；以后先验证再复用。安装移动或旧路径失效会继续查找，未发现仍可手选。未安装VM不影响纯脚本生成。

应用成功后自动将顶部目标、内部读取路径及流程/模块清单推进到本次已独立重载验证的新SOL，保持当前模块选中。随后可以切换另一流程/脚本，再配置规则并应用：下一次基于最新副本修改，之前已应用的脚本作为非目标记录逐字节保留。每次仍创建新文件，编号使用_脚本已应用_2等，不反复增长后缀。失败不推进目标。仅在生成器编辑但尚未应用的内容不是已保存脚本；切换前须先应用需要保留的修改，不提供一次并行修改多个模块的队列。

7.13将SOL设为脚本页主流程：顶部“打开SOL”，选择流程和脚本模块，配置产品规则并预览代码，直接点击同一顶部区域的“应用脚本到SOL”。三个页签切换和变量清单来源切换都不隐藏或清除该目标。预览窗口显示目标流程/模块ID、沿用及新增变量、VM目录和新方案路径；确认后导入当前生成的全部主脚本，由VM原生编译并独立重载校验，再创建新SOL。原方案及已有文件仍不覆盖，检测流程仍不执行。

7.18.3受保护方案成功打开后，密码在当前方案会话的内存中复用，预览窗口自动填入且保持隐藏，可修改；切换流程/脚本无需再填。应用成功并独立重载验证的新副本继承该会话，后续修改继续复用。打开其他方案或关闭工具箱时清除，读取密码错误时清除错误凭据；取消预览清空窗口字段，但保留已经验证的会话。应用失败清除本次任务候选密码，不将它作为新副本的成功凭据。新方案保持原密码保护，密码只通过子进程stdin传入，不进入命令行参数、配置、应用日志、快照或任务文件。CLI仍逐次使用stdin，不增加磁盘记忆。应用需要本机完整VisionMaster x64 SDK及.NET Framework编译器，已验证VM4.4.0；未安装VM仍可读取变量、生成/复制/保存代码。

输入/输出同名同类型时保留原上游/下游绑定，不删除原变量。7.18.3允许五项固定输入和四项标准输出缺失，预览明确列出新增项，按当前模板的实际端口名补齐；已有输出可为目标四项的子集，未知额外输出仍拒绝，避免下游读取旧值。已有同名异类型仍拒绝，产品独立XXXResult缺失仍不能猜测上游；可先用“使用此模块变量”导入实际信号再配置规则。

aiResult或Label_name任一缺失时自动关闭当前生成代码的AI判定，避免未绑定的默认0或空标签参与结果；如后续确需AI，先在VM完成对应绑定，再启用生成器AI开关。其余新增固定输入同样保持未绑定，不填造NGtype、速度和存图阈值。端口补齐及原生编译通过不代表工位输入配置完成或检测流程通过。

应用或离线测试期间，顶部SOL路径/打开/流程/模块/应用区域与配置一起锁定，完成/失败后恢复；应用时禁用配置和目标编辑，后台显示阶段；完成/失败后恢复操作。关闭主窗口会等待任务完成。请先保存并关闭VisionMaster，避免其与SDK同时使用安装目录下的脚本编译环境。工具箱应用任务使用跨进程互斥锁，不中断用户其他进程。SDK阶段每次最多120秒，异常不交付方案；磁盘失败会删除本次创建的不完整输出。

## 保存与验证

全量SDK另存会正常重写模型临时路径、AssemblyGuid、图像源当前路径及存图UI缓存。工具不会直接交付这种全量另存：先让VM生成目标模块的完整原生参数记录，然后仅回填该记录，其他模块记录以及原ZIP资源文件保持原样。只组合已核验的版本7外层记录边界，不构造或猜改模块内部参数二进制。未知版本拒绝写入，版本5仍可只读检查。

7.18.3保留原ZIP容器表示，不再将所有条目解密、重压缩和重新生成头。先在私有临时副本中使用本机VM自带SharpZipLib的ZipFile更新MoudleFrame，禁止把新目标条目升级为ZIP64，密码仍仅在内存/stdin中；该阶段仍会规范化部分非目标头，所以它的文件不直接交付。随后仅提取其目标frame的原生压缩/加密记录，将原方案所有非目标local record（局部头、原压缩/加密字节及描述符/间隔）原样复制，并保留原central header，只有条目在新文件中的位置offset重算。原条目顺序、归档comment和非目标中央目录元数据保持原样，不携带/分发厂商DLL，不猜改VM内部坐标或模块参数二进制。

ZIP外层依据[PKWARE APPNOTE](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT)的标准目录格式：中央目录固定头46字节，其local header相对位置字段在+42；只更新该4字节offset，其他非目标中央目录字节保留。检查单卷、数量、局部头及中央目录名称、压缩块边界、EOCD目录边界、尾部comment和文件终点；最多30000条目、文件不超过2GB。未知ZIP64中央目录/EOCD、分卷、自解压前缀、扩展尾部均明确拒绝，不尝试自动修复。原文件已有的局部ZIP64 extra可作为不透明局部头保留，不等于允许新建ZIP64中央目录。

除完整外层记录长度、非目标模块记录逐字节一致、VmServer拓扑/绑定一致及目标完整UTF-8源码外，最终校验还逐项核对非目标local record SHA-256和中央目录原始字节（仅排除offset）、CRC/长度、名称、加密标志、压缩方式、DOS日期、extra、comment、属性及版本需求。原目标中央目录版本需求小于45时，不允许新目标升到45及以上。仅CRC一致不再作为容器保留证据；不符不交付。成功结果兼容附加non_target_archive_raw_preserved=true、preserved_zip_entries，表示非目标ZIP条目原始表示通过核验，不表示VM界面布局已实际验证。

封装副本再由独立SDK进程重新加载、检查端口并另存验证文件；确认源码仍在后才独占创建最终新文件。SDK重载后的全量另存只用于核验，不作为交付文件。原文件SHA-256在前后核对。SDK加载/编译成功不等于现场相机、通信、模型及检测结果验证通过。

实现：sol_apply.py负责计划、互斥、临时文件、SDK适配器编译及验证；vm_bridge/SolScriptHost.cs使用VM原生动态端口、ShellContent文件导入、AddInputParam/AddOutputParam注册、SetShellContent编译及SaveAs。使用公开Modules集合递归获取模块ID，处理SDK模块对象懒加载，不通过名称猜目标。适配器不调用Run或SilentExecute；不会接管已打开的VM界面。

7.18.3新增端口以VM原生`%实际变量名%`创建，随即核对端口存在与类型，再进入完整输入/输出注册和脚本编译。本机SDK的AddIO不会自动给裸名称添加百分号，旧实现随后按百分号筛选时漏掉新端口，造成aiResult等名称不存在；此修复不向C#主脚本中拼接未经注册的临时属性，也不修改已有端口绑定。

## CLI

```powershell
VTStudioCLI.exe script-apply --sol input.sol --module-id 9 --config product.json --output output-new.sol --vm-apps "D:\VM\VisionMaster4.4.0\Applications" --password-stdin
```

加密方案的密码从stdin单行读取；不提供--password参数。非加密方案省略--password-stdin，不交互提问。--config缺省为示例产品，--preserve-from可保留已有脚本两个USER CODE区。返回输出路径、目标ID、原生compile结果、reloaded/source_verified/other_records_unchanged/bindings_unchanged/source_unchanged及flows_run=false；不覆盖，失败退出1，参数错误退出2。

7.17成功结果兼容附加metadata，包含最终输出path和独立重载后的全部脚本变量元数据，供GUI继续编辑同一方案的其他模块；不含密码。CLI连续修改时也须将上一次output作为下一次--sol。
