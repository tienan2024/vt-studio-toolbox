## 合成过程

1. 在 NG 原始像素坐标中记录选区顶点；按外接矩形裁出素材并生成多边形掩膜。
2. 背景参考值为选区外接矩形外扩 12%（最少 8 px）环带的第 65 百分位；无环带时为素材第 90 百分位，至少为 1。RGB 分别估计三个通道并保存 `reference_rgb`，同时保留亮度标量 `reference_gray`。设置 `reference_gray` 非零时三个通道共用该手动值；RGB 素材未携带通道参考值时也使用标量。
3. 根据指定种子依次抽取尺度、角度、强度，变换素材和掩膜，在允许区域内均匀抽取放置位置。最多尝试 80 次，过大或无像素变化时重新抽取，耗尽后明确报错。
4. 羽化在掩膜零填充后高斯模糊，映射为内部软边权重，并乘以原掩膜，将变化限制在选区内部；0 表示关闭羽化。
5. 暗缺陷：`transfer = base * clip(donor/reference, 0, 1)`，RGB 按通道运算。纹理粘贴：`transfer = donor`。最终 `result = round(base*(1-alpha)+transfer*alpha)`；`alpha` 为单通道软边权重乘混合强度，在 RGB 的三个通道上广播。旋转补边使用对应的参考颜色，掩膜外权重仍为0。
6. 各通道量化到 8 位后，以任意通道与原图不相等的像素生成 L 模式二值掩膜，计数和包围框按像素计算。全图尺寸、颜色模式、坐标与选区外像素保持不变。BMP 输出为灰度8位或RGB24位。

上述公式是图像合成近似，不构成立体缺陷、透射光或散射光成像模型。

## 参数

`Settings` 定义 `mode`（darken/texture）、`scale_min/max`（0.02～5）、`rotation`（0～180°，采样 ±）、`strength_min/max`（大于0且不超过1）、`feather`（0～100 px）、`reference_gray`（0自动，1～255手动）、`samples_per_ok`（1～1000）、`seed`（0～2147483647）、`class_name`（1～80字）、`roi`。

`roi=[left,top,right,bottom]` 使用 0～1 比例，最小边界向下取整、最大边界向上取整映射到每张底图。它仅适用于同款、位置关系一致的底图，不自动做产品定位或尺寸标定。

6.2允许在完整NG上另框生成范围，GUI将矩形除以NG宽高后写入同一个 `Settings.roi`，在OK上显示比例映射后的范围。素材提取选区与生成范围独立，切换模式和清除范围不改写Asset。旧OK直接框选继续可用；保存/加载配方与CLI不改变roi字段或坐标契约。缺陷的整个旋转后外接矩形必须放进区域，不仅约束中心点；放不下时按原引擎规则报错。详见 [操作与边界](05-NG生成范围.md)。

Canvas支持独立的ROI/原位置引导层；NG提取为蓝色实线、ROI为绿色实线、原位置参考为蓝色虚线。原位置取Asset来源bbox，按来源source_size归一化再映射到画布；该参考层不参与合成。配方只有嵌入素材裁图而原NG不可恢复时，禁止在该裁图上框NG生成范围，防止使用错误坐标系；已保存的roi仍生效，并可在OK上微调。

## 位置记录

`schema` 为 `vt-defect-lab/1`，每张图包含：

- 来源：`source_ok`、`source_defect`（原 NG 路径、尺寸、圈选顶点和外接矩形）、`split_group`。
- 图像：`image`、`mask`、`annotation` 批次相对路径，`image_size=[width,height]`、`image_mode=L|RGB`、`synthetic=true`、`class_name`。
- 合成：`seed`、`mode`、`scale`、`angle_degrees`、`strength`、`feather_px`、`reference_gray`。
- RGB 记录额外包含实际使用的 `reference_rgb=[R,G,B]`；素材来源新增 `source_mode`。掩膜仍为单通道，不按颜色通道计数。
- 几何：`placement_xyxy`、`bbox_xyxy`、`allowed_roi_xyxy`、`changed_pixel_count`。
- `bbox_convention=zero_based_half_open`；原点左上，x 向右、y 向下；框的右/下边界不包含。
- `mask_definition` 声明 255 为量化后实际变化的像素，0 为未变化，不保证与人工语义分割一致。

## 配方与批次

配方以 schema、settings、asset、ok_paths 组成；asset 中包含 L/RGB PNG 与 L 掩膜的 Base64、参考灰度和来源信息，RGB 可含 `reference_rgb`（3个1～255有限数值）。PNG 无损，加载时检查模式、尺寸、掩膜与数值范围。旧灰度配方和素材仍可读取，schema 保持 `vt-defect-lab/1` / `vt-defect-asset/1`；RGB 内容需工具6.1或更高版本，旧版不能读取。配方/素材 JSON 最大340MB，像素 PNG Base64 最大245MB，掩膜最大85MB，图像像素上限不变。原 NG 文件不是恢复素材的必要条件。源路径失效或图像内容发生改变时，不自动推断其他文件。

批次创建前检查底图格式与首次放置是否可行。运行目录带本地时间与 UUID 后缀；每张生成图带全局序号，重名源文件也不会冲突。原图不写入，不裁切或填边。完整完成记录写入 `manifest.jsonl`；取消/异常将最终状态写入 `summary.json`。写盘错误时可能留下未进入 manifest 的文件；仅处理清单中的完整样本。

不同批次不覆盖。取消不删除已完成图像。输入路径不接受自动执行或联网；工具没有 API Key 配置。

6.3 GUI和CLI素材池使用 `vt-defect-pool/1`，每项entry含id、name、roi和内嵌asset。旧 `vt-defect-lab/1` 单素材配方通过 `load_pool_recipe` 自动适配为单项池；原 `load_recipe` 保留原契约。池匹配策略为 `same_mode_roi_fit_seeded`：以样本种子打乱候选，按模式筛选，再以各项roi调用原synthesize，跳过放不下或无有效变化的候选。每张OK预检无候选时整个批次拒绝。取消/失败保留已完成清单及用量统计。

池结果新增 `pool_entry_id`、`pool_entry_name`、`matching_policy`、`source_roi_normalized`；`source_defect`仍记录实际使用的NG。池批次素材位于assets/，summary含pool_entries和donor_usage。pending_ng保存未圈选NG路径、ID和已框的roi，不参与匹配。单池最多200张NG，总配方340MB上限不变。完整数据格式见 [多NG素材池](06-多NG素材池.md)。

画布共用右键拖动平移：超过Qt系统拖动阈值才平移，右键单击在多边形模式收尾；拖动不提交/清除圈选。中键不再平移；浏览模式仍可左键拖动，滚轮缩放不变。

6.4 Settings新增可选整数total_samples：0保留原samples_per_ok方式，1～100000为精确批次总数。公共generation_counts按OK输入顺序分配：总数T、OK数N，前T%N张各T//N+1，其他各T//N；单素材及池批次共用该计划。仅对分配数大于0的OK读图和预检，零分配项不参与；保存配方仍保留完整OK列表。种子仍是全局seed+已完成序号，不放宽NG匹配条件。

summary新增quantity_mode（total/per_ok）和planned_ok_counts（每项source_ok及计划count），total为精确计划总数；completed及manifest仍记录实际完成数量。按每张方式保存时省略total_samples字段，保持原配方字段兼容；精确总数配方携带正值，需6.4或更高版本。旧配方缺字段时默认0。详见 [数量设置](07-批量生成数量.md)。

## 便携构建

PyInstaller 使用当前 Qt wheel 的 VC 运行库作为程序私有运行库，避免 Python 3.10 附带的旧版本 DLL 在进程启动时先被装载。脚本仅复制到实际输出目录的 `_internal`，不安装或替换 Windows 系统 DLL。必须保留完整便携目录。

Qt 6.11 在 Windows 上调用系统 ICU 的未版本化接口，不能与本机 Poppler PATH 中导出 `*_78` 符号的同名 `icuuc.dll` 混用。规格在 COLLECT 之前从 binaries 中排除未版本化的 `icuuc.dll`、`icuin.dll` 与 `icu.dll`，依赖 Windows 10/11 的 System32 实现。不会改动系统 DLL。

`build.ps1` 构建完成后直接启动所生成的 EXE，以非交互诊断方式运行导入、QThread 预览和两张图导出，核对图像模式、尺寸和掩膜。只有报告 `status=passed`、`frozen=true` 且退出码为0才算构建完成。

同一规格还生成控制台程序 `VTStudioCLI.exe`，构建后运行 `info` 检查 JSON 契约、无界面能力与RGB能力。便携GUI诊断同时运行RGB预览、两张24位BMP导出、按任意通道变化计算的掩膜及配方恢复检查，全部通过才完成构建。两个 EXE 共用 `_internal`，交付时保留整个目录及随附 docs 文档。
